# 周天下省份制度：test 分支合并与本地重构规划

日期：2026-09-10。状态：**规划报告，尚未实施合并或机制修改**。

## 1. 结论与建议

可以合并，但应当把这次工作视为一次“国家成员制度与省份疆籍制度的整合”。建议以本地 `main` 为整合基底，引入组长的省份登记、操作界面和索还机制，再逐项接入本地生命周期。不要整文件采用远端版本，也不要把所有国家成员判断替换为省份判断。

最需要重构的五处是：

1. **非法夺地**：本地根据旧主人是否为成员识别周土；远端根据省份登记识别周土。两种口径在征服、再征服时已经不同。
2. **礼制护土**：本地保护成员的全部领土；加入省份制度后，必须明确未入籍领土与被外国占有的周土是否受保护。
3. **背盟、灭亡与复国**：合并退出按钮时必须保留失爵与申请作废；强制索还复国不能绕过禁入和主动弃爵。
4. **解散周天下**：远端清理器不知道本地后来新增的王命、勤王、子升伯申请与礼制护土状态，需要补齐终止流程。
5. **天命与防御义务**：远端增加“未保护成员自动扣天命”，与本地“告急可拒绝且不罚”存在玩法冲突，不能当成普通代码冲突自动择一。

建议第一批保持公议、晋爵、盟功、王命和勤王的国家成员资格不变；将明确属于土地的规则接入省份旗标。旧档迁移不列为本次交付要求，以新战役和新版本存读档为验收基准。

## 3. 组长实际实现了什么

### 3.1 国家身份与省份身份分开保存

| 状态 | 真源 | 当前作用 |
|---|---|---|
| 普通成员 | 国家旗标 `zhx_member` | 诸侯身份；仍经 `zhx_register_tianxia_member` 登记 |
| 周天子 | 国家旗标及目标 `zhx_tianzi` | 礼乐、公议与本地天子机制 |
| 周土 | 省份旗标 `zhx_tianxia_province` | 省份登记，征服后仍保留 |
| 首次入籍奖励账 | 省份旗标 `zhx_tianxia_admission_reward_paid` | 防止退出再加入重复领取天命奖励 |
| 历史周身份 | `gdd_tianxia_historical_polity` 等 | 给灭亡国家的合法索还／复国提供证据 |
| 中华皇帝 | 原生身份与 `EmperorOfChina` 目标 | 远端的天命奖罚与索还发起者 |
| 全局解散 | `zhx_tianxia_dismantled` | 阻断周天下制度重新运行 |

因此会合法出现以下四种组合：

| 所有者 | 省份已入籍 | 省份未入籍 |
|---|---|---|
| 天子／成员 | 常规周土 | 新征服或尚未完成入籍条件的领土 |
| 外国 | 外国持有的周土，可被索还或剥离 | 普通外国土地 |

**远端没有把诸侯身份改成“首都在周土即自动成为成员”，也没有让占有周土的外国自动入盟。** 新成员登记不等于自动给全部领土登记；后续省份加入走单省／批量按钮或 AI 季度维护。[R2][R3]

### 3.2 加入、剥离、退盟与索还

| 操作 | 远端规则 | 整合时要保留的区别 |
|---|---|---|
| 新开局建籍 | 天子与成员直接持有的非神罗省份建立周土和已支付账；不奖励天命 | 初始化不套用玩家按钮的完整核心、和平等门槛；后续刷新不能重新铺满成员领土 |
| 单省／批量加入 | 所有者属于周天下、和平、自有自控、完整核心，且不在神罗或贸易公司 | 奖励逐省首次发放，每发展度 0.1、单省上限 20；批量没有额外总上限 |
| 外国剥离单省 | 外国和平、自有自控；没有待索还或拒还修正 | 扣每发展度 0.1、单省上限 20；皇帝对剥离国 -25 好感；首次奖励账保留 |
| 国家主动退盟 | 清直属周土，取消国家成员身份 | 天命损失按全部被清周土合计，上限 20；不是把单省扣款循环一遍；直属属国不是本国直属省份 |
| 非法周土索还 | 已入籍、持有者无核心、无本任解放豁免，并有合法核心接收国 | 这是当前领土状态，不要求一定由刚结束的战争产生；实际持有国独立 365 天冷却 |
| 拒还 | 省份修正、成员关系损伤、5 年解放 CB | 与本地犯盟及“奉辞伐罪”是不同触发来源；拒还本身不额外扣天命 |

索还可向属国的宗主提出，天子的直属属国存在直接处理例外；双方互相交战时禁止，各自对第三方作战允许。接受索还只转移选中的争议省，可以复立灭亡核心国，并登记普通成员，不自动授予七大诸侯席位。[R2][R3]

### 3.3 不能混称的三个数值／动作

- `zhx_ritual_authority` 是礼乐值，由本地年度演算及离散事件调整。
- 原生 Mandate 是远端界面称作“王命”的资源值，由 `add_mandate` 等路径调整。
- 本地 `zhx_wm_*` 的“王命”是贡赋、徙民、征军三项天子命令，不是上述数值。

第一批不必改内部 ID，但报告、提示和测试记录应分别使用“礼乐值”“天命值（test 界面称王命）”“王命行动”，防止把迁民操作错误接到天命资源上。

## 4. 必须处理的重构项

这里的 P0 表示进入可玩整合版本前必须解决；P1 表示同批功能验收必须覆盖；P2 为后续优化。推荐方案属于本报告建议，未确认的玩法差异不能冒充既有定案。

### P0-1：统一土地口径，分开犯盟行为与非法占地状态

**证据：** 本地 `zhx_diplomacy_on_actions.txt` 的省份易主条件依赖 `FROM = { zhx_is_tianxia_polity = yes }`；远端索还依赖 `zhx_tianxia_province`。[L1][R2]

直接合并会出现：

- 成员刚征服但未入籍的省份，又被另一国夺走，本地仍按周土处理。
- 已入籍周土先被外国甲占有，再被外国乙无核心夺走，本地因为旧主人不是成员而不记犯盟，但远端仍可能索还。

**推荐：** 新增统一省份判断接口，例如 `zhx_is_tianxia_province`，内部读取登记旗标和未解散条件。非法夺地判定改读该接口，保留“交战、无核心、合法转移令牌、责任归宗主”的本地结构；是否豁免成员从外国收复的周土，明确复用远端的解放语义。

不要直接拿“有合法核心接收国”的索还条件判断是否犯盟：没有可复国的核心国家，只意味着不能执行索还，不意味着夺地合法。也不要因为后来完成核心，就追溯撤销此前已发生的犯盟行为。

保留本地同月一次犯盟批次、灭侯独立 +5 AE、灭侯礼乐 -5、天子犯盟礼乐 -3 的现有结算口径；省份登记本身不应改变这些数值。归还事件应在实际 `cede_province` 前后正确使用合法转移上下文，避免归还对象恰与持有者另有战争时误罚。

### P0-2：礼制护土需要明示新的保护对象

**证据：** `zhx_refresh_province_ritual_warscore` 当前只检查所有者属于周天下，不检查省份登记。成员国土地通过永久省份修正获得战争分数成本加成。[L2]

有三种可选设计：全部成员土地、全部已登记周土、成员持有的已登记周土。**推荐第一批采用“成员持有的已登记周土”**：入籍才获得礼制保护，外国占有的周土仍可索还，但不因礼制护土变得更难收复。这是建议，需要在实施前作为明确玩法选择确认；若选择保护一切登记周土，需相应调整外国持有时的验收预期。

除了改判断，还须在单省加入、剥离、批量加入、退盟、初始化、所有权改变和全局解散后刷新。现有礼乐变化刷新、月度补偿继续保留。**只有土地身份改变而没有易主，也必须立即更新修正。** 清理时依据旧活动标记或实际修正查找，不可先删周土再仅扫描现有周土。

同步修改手写的 `zhx_ritual_warscore_effects.txt` 和 `tools/validate_zhx_ritual_warscore.py`；当前仓库没有对应的护土生成器。年度礼乐预估仍只作预览，不得在省份按钮刷新时重复结算年度收益。

### P0-3：所有退盟入口共用一条完整生命周期

**证据：** 本地决议先调用 `zhx_feudatory_forfeit_dignity` 再移除成员；远端决议和新界面共用 `gdd_leave_tianxia_with_mandate_penalty_effect`，该效果没有弃爵调用。[L3][R4]

建议采用远端统一入口，补入本地弃爵、请封作废、相关待办取消，并保持如下顺序：

1. 复核退出资格，保存退盟国上下文和直属已登记省份的总发展度。
2. 放弃旧爵档案，使待处理晋爵不能在退盟后获批。
3. 清直属省份登记与派生护土状态，按总额结算一次天命损失。
4. 撤销成员身份、七大席位、相关投票与缓存；刷新受影响请求。
5. 威望、禁入与关系代价各执行一次；保留既有犯盟和永久入籍奖励账。

另一个实际差异：本地退出决议的 `potential` 要求独立；远端公共 `gdd_can_leave_tianxia_trigger` 没有 `is_subject = no`，所以新界面可绕开决议的独立限制。推荐把独立条件放到公共资格内，使决议和按钮一致；是否允许附庸诸侯主动退盟，应单独设计。

### P0-4：复国不能把历史身份当成无条件准入

远端允许灭亡历史政体作为索还接收者，随后直接调用成员登记。本地历史释放与爵位恢复则检查主动背盟、禁入、恢复档案和直属关系。两者必须共享资格政策。[R2][R3][L4]

推荐区分三件事：**国家是否能因核心复立、复立后是否有成员资格、是否恢复旧爵**。历史身份只是证据，不能取消二十年禁入或恢复主动放弃的爵位；普通君主诸侯可按合规档案恢复旧爵，但不能自动恢复七大诸侯席位，更不能恢复天子职位。

必须覆盖“主动退盟→灭亡→强制索还复国”“动态入盟国灭亡→复国”“作为附庸被释放”“只剩一省的合法旧侯国恢复”。具体选择是不向禁入国索还，还是允许复立而暂不入盟，应明确为规则；不可继续让不同入口各自决定。

### P0-5：解散需要本地模块的完整退出接口

远端 `gdd_dismantle_tianxia_effect` 已清理旧公议、诸侯力量投射、部分请封和改革状态，但没有引用本地新增 `zhx_wm_*`、`zhx_qn_*` 或礼制护土清理器。[R3]

应增加模块级清理，顺序为“关闭新操作→取消待办→清修正／制度→清缓存→最后清权威目标”：

| 本地模块 | 解散必须处理的内容 |
|---|---|
| 礼制护土 | 所有活动省份修正和活动标记，立即清除 |
| 王命行动 | 三项全局 queued、诸侯待贡状态和可失效请求；不得在下个月继续征收 |
| 勤王 | 当前战役、邀请、待加入／待结算状态与目标；不得在解散后扣人情或发盟功 |
| 子升伯及上级晋爵 | 每国直接申请、共享上级公议申请、受理天子与申请者目标；逐份退出 |
| 周天子政府 | 同步失去资格的第一层改革与训练修正；扩编制度的终止语义须明确；不顺便删除现有军队 |
| 公议与礼乐预估 | 投票名单、预估显示缓存、已排队的结果事件失效 |

注意现有 `zhx_qn_close_campaign` **有意保留**旧响应的 pending／joining 状态，不能把它当成已经具备彻底解散能力；普通成员退出也不能关闭全天下的勤王战役。[L5]

全局解散是不可逆终局，退出成员则只是单国变化，两者不要复用一个会误清全局的巨型函数。保留远端 `dismantle_empire_of_china` 行为意味着原生中华帝国也会被解散，这是功能代价，需要列入验收。

### P0-6：保留统一初始化，防止跨文件同名定义复发

`6f68e6e` 已修复 v13 同时被领土与盟功定义、v14 同时被领土与外交定义的问题：版本调度集中到 `zhx_system_effects.txt`，功能分别调用 `zhx_initialise_merit_store_effect`、`zhx_initialise_diplomacy_effect` 等。[R1]

这一修复应完整保留。与此同时，保留本地同一盟功效果文件中正常换届调用的 `zhx_wm_new_term`；它属于换届流程，不应误搬成每次初始化都执行。新增验收检查跨文件 scripted effect／trigger 名称唯一，不能只查花括号。

新开局顺序应明确为：建立天子／成员→建立省份疆籍→初始化盟功／外交／爵位等依赖→刷新护土和界面。重复初始化不发奖励、不重置任期、不重新加入曾主动剥离的土地。

不为了报告建议去删除远端已有 v15／v16 路径；本次不承诺旧档修复，测试重点是新局、重复初始化与新版本存读档。远端报告的“68 国、323 块”只对应其历史覆盖，本地已改地图，不能硬编码为整合版数量。[R1]

### P0-7：防御扣款必须与本地救患、告急规则协调

远端月度维护以“成员正遭域外进攻，而中华皇帝未与敌人交战”检测失职，每段连续状态扣 10 天命；不要求曾发起求援，不要求皇帝满足本地安全参战条件。[R4]

本地告急明确允许拒绝且不罚，救患／告急还要求天子和平、目标独立且为防御领袖，并排除若干敌我关系。远端检测的是 `EmperorOfChina`，本地援助和勤王读取 `zhx_tianzi`。即使文本完全自动合并，也会出现“根本不能合法救援，仍被扣款”的规则变化。[L6]

**推荐第一批维持本地拒绝不罚，将远端自动失职扣款隔离停用；若团队决定引入保护义务，则另立明确规则与测试。** 后续可把实际求援、合法响应机会、宽限期、真实入战结果和一次性结算接成一条链，不能仅用“没有交战”代表已经拒绝。

勤王拒绝是诸侯拒绝参加天子的战争，与天子没有救援成员不是一回事，不能合并罚款标记。远端域外灭侯扣 10 天命与本地灭侯礼乐 -5／固定 AE 也须在结算表中写明是否有意叠加，而不是误认为二者是同一个数值。

### P1-1：保留国家机制，避免省份化扩大成全面改制

| 本地机制 | 推荐本批口径 | 需要接入之处 |
|---|---|---|
| 公议选民、七大诸侯、盟功任期 | 继续按国家成员身份 | 加入、退盟、灭亡时刷新资格与名单 |
| 子伯侯公晋爵 | 保留总发展度、直属城市数与本届盟功门槛 | 身份变化作废请求；暂不改为只统计已登记周土 |
| 王命贡赋／征军 | 继续按成员国收入与人力计算 | 退盟、天子失位、解散后请求失效 |
| 王命徙民 | 暂保留现有成员全部自有城市候选与天子首都区域接收 | 若以后限定只能从周土迁民，支付能力判断、逐点扣除和接收区域必须一起修改 |
| 勤王、救患、告急 | 继续按成员身份和真实外交／战争关系 | 不因占有周土而邀请外国，也不因迁都自动取消成员身份 |
| 共同改革投票权重 | 第一批保留国家总发展度 | 远端仍使用 `total_development`，并未自动改成周土发展度 |
| 双都王畿税收 | 保留省份 688、1836 与天子制所有者条件 | 不因全图省份制度扩散到其他省份 |
| 楚开局、共和政府、学派、学宫 | 保留现有机制 | 索还造成易主／复国时经过既有回调并验证缓存 |

### P1-2：天子、中华皇帝与 CZH 数据锚点保持职责清楚

这三个对象目前并不完全等价。不要为了“统一身份”全局替换 `CZH` 或 `EmperorOfChina`。

建议第一批保持现有 CZH 数据锚点，分别封装天子职责和原生天命持有者职责，并确认目标有效性。至少测试两个职位同国、异国和原生天命更替。远端领土季度事件本身仍要求 `tag = CZH`；若要宣称支持 CZH 灭亡后天下继续运行，须另做锚点迁移，改一个扣款目标并不能完成支持。

远端新增灭侯天命扣款直接挂在 `on_annexed`／`on_integrate`／`on_diplomatic_annex`。本地既有稳定性原则是在这些回调只记录去重与队列，月度安全边界结算。建议新增天命损失也纳入队列，记录实际责任与对应权威，明确权威在结算前变更时的归属；这是减少回调负担的整合建议，**不是已证明该 `add_mandate` 路径会崩溃**。

### P1-3：不要让界面／生成器覆盖掉真实规则

- 保留本地公议投票国家名册和 `zhx_prepare_ritual_order_tooltip`；远端“旧盾牌网格已退休”的判断不能用于删除新名册。
- 同步修改 `generate_zhx_tianxia_roster.py` 和生成的效果。先解决生成器，再在隔离整合目录生成；只改输出会被下次生成抹掉。
- 保留远端省份界面的神罗／贸易公司共享位置遮罩设计，在 macOS EU4 1.37.5 实机验证正常、悬停、禁用、点击穿透、欧洲神罗与普通贸易公司省份。离线布局和 Windows 参考不替代本机验证。
- 远端用贸易公司状态优先的回调清除周土，属于不经普通剥离按钮的边界路径；需明确是否免除剥离奖罚，并立即刷新护土与索还状态。开局登记只排除神罗，没有排除贸易公司，要检查最终历史覆盖是否可能触发这条修复。
- 源中文和编码 `.yml` 作为一对合并。先核对两边编码产物是否有独有键，再统一可读源并生成，防止丢字或丢键。
- 本地 `gdd_celestial_test_triggers.txt` 与 `gdd_celestial_action_triggers.txt` 已重复定义三个基础 trigger；远端删除了前者的重复定义。保留这一去重，**保住 action 文件内本地“周天子制暂禁旧贤能圣旨”的条件**，不要为了处理冲突重新保留两份定义。远端共同改革门槛从 80 天命且稳定至少 -2 改为 50 天命，也是额外玩法变化，要单独记录取舍。

### P2：性能与文件维护

远端加入／剥离奖励按最多 200 点发展度逐次循环，每次搜索皇帝；季度遍历国家与自有省份，天命月度也扫描国家领土，本地另有护土维护。先用固定测试局测量月底和季度耗时，再考虑复用权威目标、合并只读扫描或维护脏标记。

不要为了优化引入未经核实的“动态变量直接加天命”语法，也不要让 GUI 刷新重新结算资源。可逐步把 `gdd_tianxia_territory_effects.txt` 拆为入籍、索还、维护和终止模块，保留公共调用名以减少改动面。
