# 王命处理：保留原窗口，改革改用权威

2026-09-12，分支 `codex/wangming-authority`。用户要求保留原王命窗口和龙形入口，并使旧王命不再影响玩法。当前完成了可脚本控制部分的停用，以及权威改革的游戏内验证；尚未证明原生皇帝身份的全部引擎硬编码行为完全中性。

## 改革规则

- 通过或主动撤销一项改革，消耗执行方一侧的 60 权威。
- 继续使用 CZH 上的有符号权威变量：中央为正，地方为负；足额支付后向零移动，保留余额，不跨零。
- 天子和首席诸侯沿用现有执行资格。通过改革仍检查前置改革及严格的发展度多数；AI 还须自身支持。
- 主动撤销可单方面执行，保留原有关系反弹。确认时重新检查资格、余额和改革状态。
- 权威不足、重复点击或表决条件失效均不能完成交易。改革不会因为支付后失去执行资格而自动消失。
- 原有权威积累、衰减、修正不变。20 点贤能的旧圣旨交易保留，贤能系统重做另案处理。

## 原窗口如何保留

新开局将 CZH 保留为原生皇帝，以维持硬编码窗口和入口。隐藏窗口中的旧天命数值、增长及原生特殊待遇按钮；保留现有改革、圣旨、诸侯与权威组件。没有修改 topbar/menubar 入口，龙形入口下的原生 50 显示仍存在。

旧天命默认设为 50，月度来源归零，正负天命及失去天命的静态修正清空。原省份入籍奖励、退籍和退盟扣费、吞并损失、事件奖励等不再改变天命，也不转为权威；其余政治后果保留。改革表决 AI 不再读取天命加分。

争夺天命 CB 被禁用，原生获得／失去天命回调不再改政体、等级、宗教、稳定度或任务。可见脚本中的原生皇帝待遇通过恒假脚本条件隔离；窗口初始化和保留的旧圣旨所需身份检查例外。旧的公开效果 ID 保留为空操作，方便既有调用兼容。

## 验证

EU4 1.37.5.0，修改后主菜单校验码 12f1，启用本模组及两个既有汉化模组。使用独立新局，原有手动存档未改动。准备脚本只设置权威及支持条件，真正改革、撤销均通过原窗口按钮执行。

| 操作 | 实测权威 | 实测改革状态 |
|---|---|---|
| CZH 通过改制科举 | 60 → 0 | 全局与 CZH 标记成立 |
| CZH 主动撤销 | 100 → 40 | 全局与 CZH 标记清除 |
| YAN 首席诸侯通过 | -60 → 0 | 全局与 YAN 标记成立 |
| 重新加载中央改革后存档 | 0 | 改革仍已通过，原入口正常 |

四份实际存档的原生天命均为 50，CZH 稳定度均为 0。存档路径、哈希及字段记录见 [save_observations.json](runtime_evidence/wangming_2026-09-12/save_observations.json)。运行时截图已在任务中展示。

相关源码模型测试 82 项通过：权威交易 8、领土按钮 33、领土状态 32、省份集成 9。另通过窗口布局、领土契约、王命载体隔离和本地化编码检查。系统 Python 缺少 PIL，相关检查使用附带 Pillow 的工作区 Python 完成；初次环境失败及最终通过均记录于 [检查结果](runtime_evidence/wangming_2026-09-12/check_results.json)。`git diff --check` 在修正变更行尾空格后通过。

启动和读档日志中没有发现本次新增条件、效果与窗口的定向错误；日志仍有继承的任务／地图区域引用错误，不能称为全日志干净。新局曾在准备时运行到 1445-01-17，此后交易测试均暂停进行，这不构成严格的长周期平衡测试。

## 维护与未覆盖范围

为停用原生身份的脚本分支，引入多份 EU4 1.37.5 整文件覆盖。85 个继承／脚本覆盖文件及来源哈希记录在 `tools/gdd_mandate_carrier_overrides.json`。升级游戏或叠加其他修改同名文件的玩法模组时，需要重新合并和审计，不能直接套用。

保留原生身份意味着引擎仍认识这个皇帝。当前验证不涵盖所有硬编码外交评分、资格限制、灭国后的入口生命周期和所有旧存档状态；“对游戏完全无影响”仍是未完全验证的要求。已知可脚本控制的增减与待遇已停用，不把测试边界当作对硬编码中性的证明。

贤能值与关联旧圣旨的进一步设计、权威积累速度及统一终局细节另案处理。临时游戏目录准备脚本已删除；测试存档及自动存档备份保留，游戏停留在暂停的中央改革测试存档。
