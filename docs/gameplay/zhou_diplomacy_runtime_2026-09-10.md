## 本轮修复

1. 去掉引擎不支持的 `trigger_value:<自定义触发器>` 导出，布尔原因使用普通触发器分支。
2. 算术临时变量先用原生导出注册到本地变量池；当前国家数值导出省略 `who=THIS`。原先源码模拟通过但实机总数为 0 的问题已复测修复。
3. 去掉 EU4 不支持的 `PREVPREV`，战争与敌方领袖比较使用明确天子目标及 `PREV`。
4. 净值绝对值改用符号选择，避免 −3000 等大值平方时定点数溢出；正负小项仍可安全使用平方根。
5. 勤王入口对属国隐藏。
6. 玩家事件的 `else` 送达分支在测试中生成 pending 却未见弹窗；独立的 `ai=no` 分支对照可显示。采用显式玩家/AI 两个分支、玩家次日事件，最终完整分发复测结果见下方更新。

## 已知问题与覆盖边界

- **同一场防御战争退出后再告急：界面显示接受，但没有实际重入。** 原版 `join_all_defensive_wars_of` 直接调用也未重入；新战争告急成功。不能仅凭该对照判定是停战还是既有参战记录限制。此边界尚未修复，不计全通过。
- 分类置顶、默认展开并非本次已实现内容；实际仍遵循原版列表顺序与展开状态。
- 敌方盟友/停战、全部人力与债务档位主要由源码组合校验覆盖；本轮不声称每一档都做过 UI 实测。AI 月度自动发送也未单独完成端到端实测。
- error.log 仍有原项目的地图/任务等警告，以及隐藏事件缺标题和启动阶段事件目标提示；不声称全局日志清洁。本轮已消除实测评分路径的未知导出、PREVPREV 与变量计算错误。
- 初次玩家拒绝断言沿用了先前 10 盟功/75 人情，夹具基线已因其他行动及月度关系变化而失效；随后用明确 0 盟功/100 人情隔离重测通过。保留失败记录，避免将夹具错误伪装成通过。
