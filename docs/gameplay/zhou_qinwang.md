## 玩家入口与规则

外交页“周天下”分类包含两项勤王入口（分类改动见 [周天下外交分类](zhou_diplomacy_category.md)）：

- **邀请勤王**：立即记录本次战争并发送。AI 诸侯依据评分处理，玩家诸侯收到接受/拒绝事件。无需同盟。
- **勤王意愿**：面向 AI 诸侯的只读条目。悬停原版接受度图标查看逐项赞成/反对；该条目本身不能发送。

两个条目是实现上的折衷：`require_acceptance=no` 可在实际发送时保存战争快照，但原版会隐藏接受度图标；`require_acceptance=yes` 显示原生理由，却没有可用的发送时效果钩子。不能到延迟接受时才猜原战争。故发送与意愿拆为两个条目；此呈现尚待实机检验，不称为原版单按钮完整复刻。

天子必须独立、恰好参与一场战争且担任本方战争领袖；诸侯必须是独立周天下成员且处于和平。进攻、防御及对其他诸侯的战争都可邀请。天子对目标至少有 25 人情。

实际入战后扣天子对该国 25 人情，同时给该国 10 主动盟功（可用、本届、终身三本账）。拒绝、资格过期或未确认参战不扣人情、不发奖励。普通单独议和、战败不追回已得奖励。

每国每战最多实际发送一次；待回复、拒绝、已加入后退出均不能再次受邀。未达到资格或 AI 意愿不足而未发送不占次数。AI 天子每月检查，没有受邀国家总数上限。

玩家接受时再次检查原战争、天子、单战、和平和人情条件。AI 同时重新检查意愿。条件失效则取消，不转用于新战争。

## 接受度

| 条件 | 分值 |
|---|---:|
| 基础 | -20 |
| 天子领导防御战争 | +30 |
| 诸侯对天子好感 | 好感 / 5 |
| 诸侯对天子信任 | (信任 - 50) / 2 |
| 人力 <25% | -30 |
| 人力 ≥25% 且 <50% | -15 |
| 贷款 1–4 笔 | -10 |
| 贷款 ≥5 笔 | -30 |
| 天子不满足单战条件，或诸侯在战 | 合计 -1000，只算一次 |
| 与敌方战争领袖有停战 | -1000 |
| 与敌方战争领袖结盟 | -1000 |

好感与信任项遵从本机原版接受度的逐项向零截断规则（如 20.8→20，-0.5→0），避免界面与实际 AI 结果不同。整数总分必须 **>0**；0 分不发送。AI 不掷随机数。

`tools/build_zhx_qinwang_score.py` 同时生成原生理由项和月度 AI 的即时计算；没有每月缓存意愿造成的显示滞后。原版意愿图标是否对禁用的只读条目正常显示，仍需启动后检验。

## 脚本结构与时序

- `common/new_diplomatic_actions/zhx_qinwang_actions.txt`：邀请与只读意愿入口（生成文件）。
- `common/scripted_triggers/zhx_qinwang_triggers.txt`：成员、战争、请求资格。
- `common/scripted_triggers/zhx_qinwang_score_triggers.txt`：共用评分（生成文件）。
- `common/scripted_effects/zhx_qinwang_effects.txt`：记录、发送、参战、结算、维护。
- `common/on_actions/zhx_qinwang_on_actions.txt`：月度 AI 与战争结束清理。
- `events/zhx_qinwang_events.txt`：玩家回复、一次性次日结算、失败通知。
- `localisation_source/032_zhx_qinwang_readable_utf8.txt`：中文真源；编码至 `replace/032_zhx_qinwang_l_english.yml`。

发送先保存 host、敌方领袖、阵营和本次计数。每个受邀国复制本次计数，事件保存自己的邀请者目标。待回复或待结算时不允许新请求覆盖快照。

原生参战效果返回后检查是否已在原战争同一阵营；若尚未可见，仅安排一次次日检查。实际参战才能扣费记功，结算标记随即清除，重复执行不再支付。这里没有无限自调度事件。

结束记录和暂停邀请是两件事：天子暂时进入第二场战争、诸侯单独议和均保留原记录。`on_war_ended` 仅在回调的双方匹配保存的两位战争领袖时清理；月度维护在原天子灭亡、失位或完全和平时兜底清理。

## 原生依据与未验证边界

只读检查本机 EU4 1.37.5 macOS 原版：

- `common/new_diplomatic_actions/00_diplomatic_actions.txt`：埃亚莱特行动同时使用 `join_all_defensive_wars_of`、`join_all_offensive_wars_of`；人情方向以受邀国 `owes_favors` 与邀请国 `add_favors` 为依据。其文件头声明 AI 不主动发起完全脚本化外交行动，因此使用月度事件。
- `CScriptedAIAcceptance::CalcValue` 在 `0x100991643` 一带逐项将千分固定点数转为整数，再累加；`CRoundVariableEffect::Execute` 在 `0x10057b84c` 一带区分正模式向上、负模式向下，生成器以相反符号模式实现向零截断。
- `CJoinOngoingWarsEffect::Execute` 构建原生召集命令；不得假设点击本身已完成参战。
- `CDiplomaticActionItem::Update` 在 `0x100d3dbec` 一带依据接受要求显示/隐藏 `ai_accept`。两条目解决展示与发送快照的冲突，仍须看实际渲染。

**尚未找到可导出并保存的原生 war ID。当前战争记录是脚本计数，不是原生唯一战争 ID。** 单战判断依据当前敌对国家中的不同敌方战争领袖，不使用原版累计胜负场次 `num_of_wars`。普通引擎不允许同一敌对组合重复参战这一边界仍须实机核验；控制台强造重叠战争不在模拟保证范围内。

以下是运行前必须明确的剩余限制：

1. 必须核验战争结束回调在白和、正常主战结束及同月对同国再次宣战时的行为。若某种结束路径绕过回调且天子始终在其他战争中，月度“和平”兜底不能精确识别战争替换。不能以源代码模型代替这项验证。
2. 记录期间战争领袖变化会使邀请暂停。若旧领袖组合不再可核对，则保守保留记录直至天子和平/失位；不能声称已完全支持领袖更换。
3. 一次性次日结算需要验证真实命令生效时机；尤其检查确认接受后、次日结算前人情被其他操作花费的边界。当前没有预扣款或人情托管。
4. 外交只读条目的原版评分显示、玩家事件自然投递、非同盟加入进攻战、人情 DLC 条件和存读档均待实机检验。
5. 灭亡后重新释放、异常脚本删战等特殊生命周期尚未覆盖；当前不承诺旧档兼容。
